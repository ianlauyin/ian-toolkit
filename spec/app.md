# App

This file is the catalog of the local app in `app/`.

Each row has the entry path, a short description, and the open behaviour. Update that row in the same change when you make a new decision, the entry moves, or you add or remove a feature. When a code change would change the open behaviour and you did not make that decision, stop and ask. Leave the decision as it is.

| path | description | decision |
| --- | --- | --- |
| `app/src/main.rs` | Local HTTP server | The server listens on `http://127.0.0.1:47322`. A route returns JSON. A route with no data returns `null`. An error returns `{"error": "<reason>"}`. A bad request returns 400. A body that is not JSON returns 415. A JSON body without a necessary field returns 422. A failed DB call returns 502. A failed read of `conf/projects.json` returns 500. `GET /` and each page path return `app/web/index.html`. Each other `GET` returns a file from `app/web/`. |
| `app/web/index.js` | Page shell | The nav has a link for TODO, Notes, and Logs, and it marks the current page. The nav stays off the right edge and slides in when the pointer is at that edge. `/` and an unknown path show `/todo`. |
| `app/src/page.rs` | Saved page data | One page has one JSON value in the local DB, stored by page name. `GET /page` returns that JSON, or `null` when the page has no save. `PUT /page` replaces the last save. A page name has only letters, digits, and `-`. |
| `app/web/design-system.css` | Design tokens | The page uses a warm ivory background, a clay accent, and serif headings. This file holds each color, font, radius, and shadow as a token, and a `prefers-color-scheme: dark` block holds the dark value. Page CSS uses these tokens for color, font family, radius, and shadow. |
| `app/web/todo/` | TODO board | The page is a board with three columns, in this order: Pending, Ongoing, and Reviewing. A card has a required title, an optional detail, and an optional deadline. Add puts the card at the end of Pending. The user drags a card to change its order or its column. Delete asks for confirmation. Each change saves the three lists as the page data `todo-items`. An old save loads into Pending. A failed save keeps the last saved lists. A failed load disables Add. |
| `app/web/notes/` | Notes page | The page shows one tab for each project, in the order of `conf/projects.json`, and selects the first tab when it opens. A note is plain text. Assign task starts one local agent, then the card shows Assigned, the chat id, and the progress. The progress loads again each 3 seconds while the agent works. After the agent finishes or stops, the card accepts a follow-up to the same session. The notes and the assigned chat ids stay in the page data. When the agent fails after the fallback, the page clears the assigned task. |
| `app/src/notes.rs` | Project list and note assign | `GET /projects` returns each project in `conf/projects.json`. `POST /notes-assign` starts one local agent in that project folder, gives the note text as the task, tells the agent to obey `AGENTS.md`, and returns the chat id. An empty note or an unknown project returns 400. |
| `app/src/open_behaviour.rs` | Local agent run | The first agent is a local Cursor agent on Claude Sonnet 5.5 with medium effort. It can edit files and run commands with no approval, and it calls no subagent. The agent continues when the page closes or the server restarts. When that agent fails, a local Grok 4.7 agent with high effort takes the same task. `GET /open-behaviour-progress` returns the status and the steps of the chat. `POST /open-behaviour-followup` sends text to the same session after the current run has ended, and a failed follow-up does not start the Grok agent. A bad chat id, an empty follow-up, a chat with no log, or an agent that still runs returns 400. |
| `app/web/logs/` | Logs page | The page shows one tab for each log server, then one tab for each app of the selected server. It opens on the first server, the first app, and the current HKT date. It shows the events of that date, newest first, in pages. The user sets the date, the page size, and filters. A filter is a field path and a value, and an event must pass every filter. A long cell shows its full text in a modal. The page uses the full window width. The control panel does not keep its state. |
| `app/src/logs.rs` | Log events | `GET /logs-apps` returns the servers and the apps in `conf/log-server.json`. `GET /logs-events` applies the filters, then returns one page of events for that server, app, and date, newest first. The read uses the method of `skills/fetch-logs.md` and keeps at most the last 1000 events of the date. A bad server, app, date, page, page size, or filter returns 400. A failed read of the config file or of the log server returns 500, and the reason does not contain the key. |
