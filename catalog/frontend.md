# Frontend

Each row has the entry path, a short description, and the open behaviour. Update that row in the same change when you make a new decision, the entry moves, or you add or remove a feature. When a code change would change the open behaviour and you did not make that decision, stop and ask. Leave the decision as it is.

| path | description | decision |
| --- | --- | --- |
| `frontend/index.html` | App name | The app name is Ian Toolkit. |
| `frontend/src/index.tsx` | Page routes | The page uses SolidJS and `ian-framework-fe`. It does not use Logger. `/` and an unknown path show `/todo`. The page calls the server through `ajax`. |
| `frontend/src/context.ts` | Version | The page reloads when `GET /version` returns a different version. |
| `frontend/src/component/Shell/` | Nav | The nav has a link for TODO, Notes, and Logs, and it marks the current page. The document title is TODO, Notes, or Logs. The nav stays off the right edge and slides in when the pointer is at that edge. |
| `frontend/src/style/tokens.css` | Design tokens | The page uses a warm ivory background, a clay accent, and serif headings. This file holds each color, font, radius, and shadow as a token. Page CSS uses these tokens for color, font family, radius, and shadow. |
| `frontend/src/style/theme-dark.css` | Dark tokens | A `prefers-color-scheme: dark` block holds the dark value of each token. |
| `frontend/src/page/todo/` | TODO board | The page is a board with three columns, in this order: Pending, Ongoing, and Reviewing. A card has a required title, an optional detail, and an optional deadline. Add puts the card at the end of Pending. The user drags a card to change its order or its column. Delete asks for confirmation. Each change saves the three lists as the page data `todo-items`. A save that has the list important or the list items, or a card field text, loads into Pending. A failed save keeps the last saved lists. A failed load disables Add. |
| `frontend/src/page/notes/` | Notes page | The page shows one tab for each project, in the order of `conf/projects.json`, and selects the first tab when it opens. A note is plain text. Assign task starts one local agent, then the card shows Assigned, the chat id, and the progress. The progress loads again each 3 seconds while the agent works. After the agent finishes or stops, the card accepts a follow-up to the same session. The notes and the assigned chat ids stay in the page data. A failed save keeps the last saved notes and the last saved chat ids. When the agent fails after the fallback, the page clears the assigned task. |
| `frontend/src/page/logs/` | Logs page | The page shows one tab for each log server, then one tab for each app of the selected server. It opens on the first server, the first app, and the current HKT date. It shows the events of that date, newest first, in pages. The user sets the date, the page size, and filters. A filter is a field path and a value, and an event must pass every filter. A new filter on one field replaces the old filter on that field. The filter list has each column and each key of context and of extra. Each field of an event has one column, in the order that the page first sees the field. The context column and the extra column are after those fields. The error_message column is the last column. The id field has no column. A long cell shows its full text in a modal. The page uses the full window width. The control panel does not keep its state. |
