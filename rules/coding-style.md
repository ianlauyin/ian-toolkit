# Coding style

- Put each server area in one file under `app/src`.
- A route handler returns JSON on success.
- A route handler returns `{"error": "<reason>"}` on failure.
- Check the input first. Return early when the input is bad.
- Write a bad-request message as a short sentence. Start the sentence with a capital letter. End the sentence with a period.
- Start the text of a failed read or a failed write with `failed to`.
- Keep a helper private. Use `pub(crate)` only when a test needs the helper.
- Put each page in one folder under `app/web`, with `context.js`, `index.js`, and `index.css`.
- Keep the page state in one plain object in `context.js`.
- Call `onChange` after each change of the state.
- Keep the last saved value when a save fails.
- Export `mount` from `index.js`. Draw the page in `mount`.
- Put text from the user in `textContent`.
- Call the server only through the `api` argument of `mount`.
- Set a page error to a sentence that starts with `Failed to`.
- Nest the page CSS under one root class for that page.
- Give a shared control a class that starts with `g-`.
- Take a color, a font, a radius, and a shadow from `app/web/design-system.css`.
- Do not add a framework. Do not add a build step.
- Put a Rust test in `app/src/test`.
- Put a page test under `app/web/test`, in the folder of that page.
- Name a test with the behaviour.
- Write a comment only to give the reason. Use one line.
- Match the format of the file that you change.
